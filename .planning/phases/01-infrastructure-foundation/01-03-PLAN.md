<objective>
Attach the OTel Astronomy Shop (minimal mode) to the running SigNoz stack so that traces, logs, and metrics from every demo service land in ClickHouse, then run the project-wide port audit that closes INFRA-02.

Purpose: this plan owns Pitfall 2, the single most dangerous Phase 1 failure. The OTel demo's bundled collector exports to Jaeger/Prometheus/OpenSearch, not to SigNoz, and its config overlay arrays REPLACE rather than append (D-09) — so a naive overlay that adds a SigNoz exporter silently drops every existing exporter and, worse, an overlay that adds an exporter without re-declaring the pipelines that reference it produces a collector that starts and emits nothing. The failure is invisible: SigNoz simply shows no services, and the Phase 5 golden path has no telemetry to reason about.

Output: `docker/otel-demo/otelcol-config-signoz.yml` (the corrected overlay), `docker/otel-demo/.env` (ENVOY_PORT=8090 per D-04), `docker/compose.otel-demo.yaml` (minimal-mode service set on the shared network), `docs/OTEL_DEMO_SERVICES.md` (which services minimal mode actually runs, with per-service telemetry proof), and a clean project-wide port audit.
</objective>

<collector_overlay_contract>
The mechanism that makes INFRA-03 work, and the trap that makes it fail. From D-09 and
PITFALLS.md Pitfall 2 (source: the inline comment in the OTel demo's own
`src/otel-collector/otelcol-config-observability.yml`).

MERGE SEMANTICS: when the OTel Collector receives multiple `--config` layers, MAP keys merge but
ARRAY values REPLACE. Consequences:

  - Adding `exporters: {otlp/signoz: ...}` to the overlay MERGES into the exporters map. Safe.
  - Writing `service.pipelines.traces.exporters: [otlp/signoz]` REPLACES the base pipeline's
    exporter array entirely. Every base exporter is dropped.
  - Omitting the pipeline block entirely means `otlp/signoz` is defined but referenced by no
    pipeline. The collector starts cleanly and exports nothing to SigNoz. THIS IS THE SILENT
    FAILURE MODE.

REQUIRED SHAPE of the overlay: define the SigNoz exporter, then RE-DECLARE each of the three
pipelines (traces, logs, metrics) with the COMPLETE exporter list — every exporter the base
config had that is still wanted, PLUS the SigNoz exporter. The base config's exporter names must
be read from the actual demo repo files at the pinned version, not assumed.

TARGET ENDPOINT: `signoz-otel-collector:4317` — the SigNoz collector's service name on the
shared `incimin` network, resolved by Docker DNS. Confirm the actual service name from
`docker compose ps` before writing it; it is whatever `docker/compose.signoz.yaml` named it.
Use `tls: insecure: true` since this is plaintext gRPC on a local bridge network.

DECISION — drop the demo's own observability backends: do NOT deploy the demo's Jaeger,
Prometheus, Grafana, or OpenSearch. SigNoz replaces all of them, Grafana's 3000 collides with
memgraph-lab, and each one costs RAM against the 14GB INFRA-05 budget. If the base collector
config references exporters for backends that are not deployed, either remove those exporters
from the re-declared pipeline arrays or keep them and accept export-failure log noise — prefer
removing them, and record the choice.
</collector_overlay_contract>
