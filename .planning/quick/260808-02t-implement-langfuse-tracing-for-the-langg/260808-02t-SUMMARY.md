# Quick 02T — Langfuse tracing for the meta-agent

## What shipped

Every agent run now exports to Langfuse as one trace: the Coordinator's tool-calling turns, the
structured-output synthesis step, and the LLM calls the telemetry and knowledge sub-agents make
inside their tools.

- `src/agent/tracing.py` — `tracing_enabled()`, a lazily-resolved cached `get_handler()`,
  `trace_config()` (returns a `RunnableConfig`), `flush()`, and `reset()` for tests.
- `src/webhook/app.py` — a `trace_config(ctx, target)` adapter mapping `AlertContext` onto trace
  attributes; both targets (`agent`, `diagnosis`) traced; `flush()` in `run_alert`'s `finally`.
- `src/ui/app.py` — one Langfuse session per Streamlit browser session.
- `src/agent/diagnosis.py` — `diagnose()` and `_synthesize()` take an optional `config` forwarded
  to the LLM call.
- `scripts/verify_langfuse.py` — credentials → handler → auth → real trace delivery.
- 28 new tests. Suite: 93 passing, same 6 pre-existing failures as baseline.

## Design decisions

- **Fails open, always.** Missing package, missing keys, unreachable host, and client
  construction failure each degrade to a config with no callbacks plus one log line. An
  un-triaged incident is a far worse outcome than a missing trace.
- **A helper module, not an import-time handler in `graph.py`.** `graph.py` is imported lazily on
  purpose so a missing API key is a per-alert log line rather than a dead webhook process; adding
  an import-time Langfuse failure there would re-create exactly that problem. Trace name, session
  and tags are also per-run values that cannot be baked into a module-level handler.
- **Session = alert dedupe key** (Alertmanager fingerprint where present). Every resend of one
  firing incident groups into a single Langfuse session rather than N unrelated traces.
- **`trace_config()` returns a usable config when tracing is off**, so call sites pass it
  unconditionally and never branch on whether Langfuse is configured.
- **Callbacks are appended, never replaced.** A caller's `base` config may already carry its own
  callbacks (LangSmith is in the dev group); overwriting would silently disable them.
- **Explicit `flush()`** at run end. The SDK batches on a timer, which is wrong for both shapes
  here — the webhook's agent threads and short-lived scripts both finish inside the interval.
- **`LANGFUSE_VERIFY_SSL` escape hatch.** `llm.py` disables cert verification process-wide for
  corporate proxies, but it does so by patching `ssl.create_default_context`, which Langfuse's
  httpx client does not route through — so the opt-out has to be explicit rather than inherited.

## Deviations from Plan

**Added `langchain>=1.3,<2` as a dependency, against CLAUDE.md's "What NOT to Use".** Langfuse's
`CallbackHandler` imports the `langchain` meta-package purely to read `langchain.__version__` and
pick its v0/v1 import branch; on the v1 branch every symbol it uses comes from `langchain_core`.
Verified before adding: it resolves as exactly one additive package (1.3.14), requires
`langchain-core>=1.4.9` which the pinned 1.5.3 satisfies, and downgrades nothing — the CLAUDE.md
rationale (stale versions, shadowing) is a 0.x-era concern that does not apply to 1.x. User chose
this over a `sys.modules` version shim. CLAUDE.md amended to record the exception; project code
still must not import from `langchain`.

## Verification

`scripts/verify_langfuse.py` against Langfuse Cloud — all four checks pass, trace delivered
(`trace_id=3b8e6cc88baffcf87d5d77e73bee9e82`). A real traced LLM call was then confirmed
end-to-end with `LLM_PROVIDER=anthropic`.

The claim that sub-agent LLM calls inherit the handler through LangChain's config contextvar is
pinned by `test_callbacks_reach_llm_calls_made_inside_a_tool`, which drives a compiled graph and
asserts the handler is visible to `ensure_config()` inside the tool body. Losing that propagation
would silently empty out half of every trace, so it is worth a test rather than a comment.

## Issues Encountered

- Running `pytest` with a populated `.env` constructed a live handler and posted test traces into
  the real Langfuse project. `tests/test_webhook.py` now has an autouse fixture that strips the
  keys; `tests/test_tracing.py` already had one.
- The `fake_graph` fixture stubbed `stream(inputs, stream_mode)` and broke on the new `config`
  kwarg. Rewritten to accept it and to return the captured call, so tests can assert on the
  config a run was given.
