# Langfuse tracing for the meta-agent

Give every agent run a Langfuse trace — the Coordinator's tool-calling loop, the synthesis
step, and the sub-agent LLM calls nested inside them — so a run can be replayed from the
Langfuse UI instead of from webhook log lines.

## Why a helper module rather than a global side effect

The obvious shortcut is to construct a `CallbackHandler` at import time in `graph.py`. Three
reasons not to:

1. **`graph.py` is imported lazily on purpose** (`webhook/app.py` docstring) so a missing API
   key is a per-alert log line rather than a dead process. Adding a second import-time failure
   mode there re-creates exactly the problem that lazy import was introduced to avoid.
2. **Trace attributes are per-run, not per-process.** Trace name, session id, and tags come
   from the alert; they cannot be baked into a module-level handler.
3. **The package may not be installed and the keys may be absent.** Tracing is an observability
   nicety; it must never be the reason an incident goes un-triaged.

So: `src/agent/tracing.py`, degrading to a no-op config on every failure path.

## Tasks

1. **`langfuse` dependency** — add to `pyproject.toml`, `uv sync`.
2. **`src/agent/tracing.py`** —
   - `tracing_enabled()` — both keys present and `LANGFUSE_TRACING_ENABLED` not falsey.
   - `get_handler()` — cached singleton `CallbackHandler`; `None` on missing creds, missing
     package, or construction failure. Warn exactly once.
   - `trace_config(name=..., session_id=..., user_id=..., tags=..., metadata=..., base=...)`
     — a `RunnableConfig` carrying `callbacks` + `run_name` + the `langfuse_*` metadata keys
     the handler reads to set trace-level attributes. Returns a plain (possibly empty) config
     when tracing is off, so call sites never branch.
   - `flush()` — best-effort, so a short-lived run's spans are not lost.
   - Env: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL` (fallback
     `LANGFUSE_HOST`), `LANGFUSE_TRACING_ENABLED`, `LANGFUSE_VERIFY_SSL`.
3. **Wire the entry points** —
   - `webhook/app.py`: `run_meta_agent` and `run_diagnosis` each get a trace named after the
     alert, session = `ctx.dedupe_key` (so Alertmanager resends of one incident group into one
     session), tags = severity/alertname/target. Flush in `run_alert`'s `finally`.
   - `ui/app.py`: one session id per Streamlit session.
   - `diagnosis.py`: `_synthesize` accepts a config and passes it to `.invoke()`.
4. **`scripts/verify_langfuse.py`** — resolve config, `auth_check()`, emit one test trace.
5. **Tests** — `tests/test_tracing.py`.
6. **README** — env var table.

## Notes / constraints

- Sub-agent LLM calls (`subagents/telemetry.py`, `subagents/knowledge.py`) are invoked inside
  tools with no explicit config. LangChain propagates `RunnableConfig` through a contextvar, so
  they inherit the handler from the top-level `stream()` call and nest under the same trace —
  no change needed there. Verified by test.
- `llm.py` disables SSL verification globally for corporate proxies. That patch targets
  `ssl.create_default_context` and does not reach Langfuse's httpx client, hence the explicit
  `LANGFUSE_VERIFY_SSL` escape hatch.
- Tracing must never raise into an agent run. Every path in `tracing.py` is wrapped.
