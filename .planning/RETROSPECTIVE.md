## Milestone: v1.6 — Plugin-based Service Topology

**Shipped:** 2026-08-07
**Phases:** 3 | **Plans:** 3 | **Tasks:** 10

### What Was Built

- `ServiceNode` and `ServiceEdge` Pydantic models with `EntityMetadataMixin` enforcing source, external_id, fetched_at, schema_version, and deterministic UUID5 internal_id
- `TopologyPlugin` ABC and `TopologyManager` plugin registry with explicit dict mapping and sub-class validation on retrieval
- `SigNozServiceMap` plugin fetching topology from the SigNoz API using `httpx` + `tenacity` with exponential backoff, yielding fully validated `ServiceNode`/`ServiceEdge` entities

### What Worked

- Wave-based parallel agent execution handled all 3 phases cleanly with no rollbacks
- Entity Metadata Principle as a hard structural invariant caught a missing-provenance gap before it reached production
- Explicit dict registry over dynamic `entry_points` — kept plugin loading auditable and secure by default
- Integration audit caught the `PLUGINS = {}` empty registry gap that would have silently failed at runtime

### What Was Inefficient

- Phase 09 VERIFICATION.md was not generated by the execute-phase subagent on first pass — required a re-run of the verify step
- pytest `pythonpath` was not configured from project inception; discovered only when tests were first run
- STATE.md accumulated raw SUMMARY frontmatter blocks as literal text (copy-paste artifact from earlier sessions)

### Patterns Established

- `EntityMetadataMixin` as the mandatory base for all topology entities — extends to any future plugin output
- `TopologyPlugin` ABC as the sole interface contract; enforced at retrieval time by `TopologyManager`
- `httpx.AsyncClient` + `tenacity @retry` as the canonical pattern for all outbound API calls in production plugins
- `[tool.pytest.ini_options] pythonpath = ["."]` required for all `uv package=false` Python projects using `src/` layout

### Key Lessons

1. Register plugins at module init time (not lazily) — empty registry bugs are silent until runtime; integration audit is the only gate that catches them
2. Write VERIFICATION.md as the final task of execute-phase, not as a post-hoc check — if the subagent exits early, the gap survives until audit

### Cost Observations

- Sessions: 1 autonomous session (gsd-autonomous)
- Notable: 3 phases executed, verified, and audited in one session with zero user interventions

3. Pin transitive dependencies aggressively from day one — the numpy<2.0/GQLAlchemy and pythonpath gaps both would have been caught earlier with a project bootstrap checklist
